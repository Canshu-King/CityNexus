## Revolution: stop sending the traveler through the 'friend import' feature to make a walk
R106 lets people choose a real city, public map pin, and see source-linked places, but the original discovering traveler still cannot make a TWO-STOP personal Pocket Walk with one obvious action from the discovery screen. The R103 atomic one-tap action applies ONLY to a friend's `SHARED_PUBLIC_REFERENCE` exact lookup. R107 should build the missing **native discovery -> my walk** path:

**On mobile, I choose a city, see two grounded public places, choose their order, press 'Make this MY two-stop walk', and get my own persistent private walk card plus individually consented navigation.** I should not first share text to myself or individually save two unrelated cards.

### Product deliverables
1. On the existing authenticated ordinary DRAFT Journey discovery results, let the member choose **exactly two distinct candidates from the SAME current signed MANUAL_PUBLIC_CENTER receipt**; display name, canonical OSM source, observation age, provider truth `LIVE_PROVIDER` vs clearly marked `TEST_PROVIDER`, and UNKNOWN opening, access, price and walk ETA. Offer an optional 15/20/30/45 min walking preference. Show a user-confirmed preview. Independent buttons for 'Share these public places' (R103) versus 'Make this MY walk'; don't silently share or start navigation.
2. Add a narrow signed server action analogous to `save_bootstrap_shared_walk_pocket_walk`, but specifically constrained to **MANUAL_PUBLIC_CENTER** scope. Require same signed member/traveler, same unexpired receipt, two independently valid OSM identities/coordinates, available private rows, no ACTIVE/PlanVersion, no restricted access, and quota max three SAVED shortlist items. Reject a `SHARED_PUBLIC_REFERENCE` receipt here: the original R103 friend import MUST keep its separate authority. Validate **both** before mutation; write 2 member-private shortlist rows and Pocket Walk **atomically in the existing transaction**. If one candidate invalid/expired, shortlist full or user changed identity, no partial write, no duplicate. Reuse R100/R103 persistence and current scoped observations; do not introduce a new Place, PlanVersion, AgentRun, Booking or consent-by-proxy.
3. Restore the exact ordered saved Pocket Walk on reload, show two source-linked stops, step-1 destination-only link and stop1-to-stop2 walking map only **under separate existing map consents**. A Pocket Walk is human intent, NOT a route, proven visit, ticket, open-now or guaranteed ETA. Do not send private map center, bearer, Journey or member identity to external maps. If Valhalla route estimate is desired, request fresh separate routing consent, do not infer duration from straight-line distance.
4. Keep two-member A/B separation. Member B observing the same OSM IDs still gets their independent scoped name/coordinates/grade; A's personal Pocket Walk cannot be read, overwritten, or erased by B. If candidate expires, search parameters edit, source grade changes, pair order changes, account/Journey swaps, or a delayed save response arrives, stale controls and consent must fail closed. Take care that R105/R106 provider consent is consumed once per real external discovery; **saving local private intent does not require a second public Overpass query**.
5. When the configured provider is disabled or ZERO/PARTIAL, show a useful grounded single-place preview and source review, but disable two-stop action honestly. Reuse existing source URL validation and consent; never fabricate second stop. UI should work at 390x844 with accessible tap targets, short copy, no action burying inside technical provider debug.

## Design rule
Keep the experience shaped by an actual traveler: two places, one decisive consented save, then walk. One new durable **user action** beats ten more configuration dashboards. The Revolution exists to take users OUT into the city without faking public facts or physical presence.
