# 改半天，真的改下去了：草案版本 0 → 1，刷新还在（2026-10-22）

一句话：**接管令 P0 的「在同一份草案上改某半天 → 刷新恢复」这一格，今天用旅客自己的手验过了**——写进 `PUT .../agent/goal-tasks/{id}/draft`，版本从 0 变 1，整页刷新之后同一项还在。

## 这一趟点了什么

1. 首屏一句话：「想慢慢逛北京的古迹和胡同小吃，一天别太赶。」目的地「北京」，出发 2026-11-02。
2. 「对话」层勾上「本次允许 AI 处理旅行目标（可能产生费用）」，发送。Agent 连着问了四轮，每一轮屏上都给的是北京内容的选项，我按它给的按钮回答（不是打字）：「皇家古迹为主 每天只安排1个重头戏（如故宫、天坛/颐和园），其余时间慢慢逛附近胡同、随时吃小吃」→「故宫 + 天坛 都在城区、步行少最省力…」→「老字号集中（前门大栅栏）…适合第2天下午散步吃」。四轮回合分别 23.4 / 28.6 / 33.0 / 20.9 秒，四步 `ask_traveler` 全部 `COMPLETED` 落库（`20261022_V3_AGENT_HALFDAY_RECEIPT.txt:29`、`:30`）。
3. 切到「日程」层。改之前：`revision` 0、`slots` 空，屏上「按天调整行程 0 项安排 · 2 天」。
4. 在 Day 2（11-03）按「＋ 添加安排」，展开那一项，时段选「下午」，安排写「湖边慢走，不安排门票」，按「保存草案」。
5. 屏上原话：「草案已保存到这趟旅行，刷新页面也可以找回。」（`20261022_V3_AGENT_HALFDAY_RECEIPT.txt:21`）库里对得上：`revision` 1，只有一项，位置就是第二天的下午（`20261022_V3_AGENT_HALFDAY_RECEIPT.txt:20`）。
6. 整页刷新：同一枚任务、同一个 `revision` 1、同一项下午安排，屏上变成「按天调整行程 1 项安排 · 2 天」（`20261022_V3_AGENT_HALFDAY_RECEIPT.txt:23`、`:24`）。这一趟没有任何 4xx（`20261022_V3_AGENT_HALFDAY_RECEIPT.txt:26`）。

## 这一格是怎么被“改半天”而不是“重写整份”的

写入的门只收整份草案但带 `expected_revision`，服务端比对版本后只把这份草案换到下一版；这次改动只落在第二天的一个空槽上，第一天的安排没有被动过（屏上 Day 1 仍是 11-02 的空日程，库里 `slots` 只有一项）。并发那一面在前一棒单独量过：Agent 还在跑的时候改草案会被版本门拒掉，屏上说「服务器的草案版本发生了变化…请先确认新内容，再点上方「刷新任务」」，见 `20261022_V3_AGENT_VERSION_DOOR.md`。

## 不宣称的事

- 这一格是**旅客自己动手**改半天。让 Agent 自己改半天（“把第二天下午换成……”这一句直接落到草案）仍未验：这四轮里模型一直在问，没有自己产出 slot——它没有地点可排（这趟行程是旅客一句话建的，城市码是私有键 `CN-RV-…`，规范地名在结构化 brief 里，见 `backend/app/agent/goal_artifacts.py:81`），而公开来源那一格今天网络不通（直连 overpass / wikidata TLS 握手超时，走本机代理 `SSL UNEXPECTED_EOF`）。
- 屏上出现的故宫、天坛、前门大栅栏是模型给的话，没有落成地点行；营业时间、票价、照片仍是 `UNKNOWN`，一次外部地点供应商都没调成。
- 草案保存之后没有接着走「准备出发 → 正式方案」这一串（那是 `prepare-plan` 那条口，前一棒已在草案卡上验过它的写入），所以这一格只算“改半天 + 刷新保留”，不算“改完直接出发”。
- 本机 Chromium，不是手机在手里的点击，`USER_VERIFIED` 继续 PENDING。
