# 从地点详情到正式行程方案

手机地点卡片新增「补齐营业和费用资料 → 查询地点详情」。搜索结果已有 OSM 编号时，可读取该地点的原始详情，补齐 Photon 搜索结果未带回的营业及费用标签，再进入已有正式方案流程。

## 实际用户路径

1. 搜索地点，展开某处地点卡片的「补齐营业和费用资料」。
2. 界面说明向 OpenStreetMap 查询该地点；点击「查询地点详情」才请求。
3. 卡片更新营业时间、费用和来源。资料齐全时显示正式行程入口。
4. 选入正式行程后，到「行程」生成、查看和选用服务端方案；启动仍是单独动作。

原始来源没有提供的资料继续显示未知。若来源标记限制访问，卡片提示换地点。详情失败会保留原资料，不自动重试。

## 实现

- 新增签名 `POST /journeys/{id}/bootstrap-discovery/facts`，绑定当前成员、候选和有效收据。
- 单次请求固定为 OSM Element API，只发送地点类型和 OSM ID。最多读取 256 KiB，5 秒网络超时，不跳转、不重试。
- 详情保存到当前成员的候选观察；其他成员的观察保持独立。重复确认读取本次已存结果。
- 沿用原营业、费用、访问条件及正式方案生成器，新增查询本身不创建 Place 或 PlanVersion。
- 接口依据：[OpenStreetMap API v0.6 / Read element](https://wiki.openstreetmap.org/wiki/API_v0.6#Read:_GET_/api/0.6/[node|way|relation]/#id)。

- 既有 Photon DRAFT 测试 **3/3 通过**（前一次组合运行 10/10）。
- 390×844 Chromium 页面测试 **1/1 通过**：展开说明零请求，点击后一次请求、更新事实并出现正式入口。
- TypeScript 全量检查、Vite build 通过。
- 首次后端运行发现现有限流函数引用名错误，修正后上述节点通过。
