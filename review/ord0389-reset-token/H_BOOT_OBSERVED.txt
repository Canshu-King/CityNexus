== what this settles, and what it does not ==
It settles: with the gate in place and no token, a browser can no longer produce the demo
scenario -- which is the point of the order -- and nothing is destroyed, nothing crashes, and
no stack of codes is thrown at the visitor. The first-party boot path degrades to 'create your
own trip', which is a defensible state for a production deployment.

It does not settle whether that is the intended state for the *preview* chain, which is
started with demo_mode on and is exactly the deployment people walk through. On that box the
operator now has to configure CITYNEXUS_DEMO_RESET_TOKEN and seed out of band, or the screen
opens on the wizard. That is a decision for the commander, not for me to pre-empt by quietly
seeding the token into a shipped launcher -- which would undo the gate.
