working tree, with neither -I nor --include. By then the suite had already imported the app, so
every `__pycache__/*.pyc` printed a "Binary file ... matches" line and `restore` read as 140
backend hits instead of 4. That number was wrong and is not used anywhere; the tables above come
from committed blobs, where no pycache exists.

DECISION, and why it is not taste: the order's pair is 找回 / 还原. Of those two, 还原 already has
a meaning on another screen (2 frontend matches, in a file this slice may not touch), while 找回
has none (0 and 0). The English side had to be a word with no prior meaning at all: `recover` and
`restore` are both taken, `undelete` is 0 files / 0 matches. So this door is
`POST /api/v1/journeys/{journey_id}/undelete`, operationId `undeleteJourney`, audit action
`journey.undeleted`, and the screen word is 找回.
