# CityNexus 全面改革：Agent 负责解决问题，人负责决定旅行

日期：2026-10-18。性质：用户授权的架构、产品与交付流程改革。不是新一轮 ORD。

## 0. 这次必须改变什么

用户不应该负责找隐藏按钮、抄地图链接、逐项补数据库或理解 Journey/PlanVersion。以后用户提出目标，Agent 调用现有能力调查、规划、调整；AI、地图、日程、确认都在同一个工作台。缺一条事实只阻塞依赖这条事实的动作，不能让整个项目停工。

本规格取代 #23/#33 中仍以两站 GO、截图次数、文案轮次为主要交付指标的旧优先级。保留已有代码、历史证据和数据，不推倒重写后端。代码归并到同一 /revolution 产品，V8 作为迁移期兼容入口，不再让两个团队各自建设一套互不相通的用户体验。

## 1. 当前源码确认的根因

基线 Revolution b3c14cc46fd8；V8 f97f0f8dafe2；旧 Revolution archive a5a2f1096e0f。开始实现前重新 fetch。

1. backend/app/agent/tool_catalog.py 实际已有 20 个工具描述。runtime.py 包含来源研究、事实获取、估算、方案生成、重规划、多人决策等模型工具。不是完全没有 Agent 基础设施。
2. trial/agent_preview_app.py 的当前用户入口却只接受四种类别之一加约百字理由。它是探索分类建议，不是通用目标型旅行 Agent，不能把它标成自主规划完成。
3. MobilePlanWorkbench 把至少两处 READY_FOR_NATIVE_PLAN 作为生成门槛；TravelBriefPreview 只是轮流分配地点到日期。用户看到灰按钮与缺项，Agent 没有接手消除缺项。
4. 原 RevolutionMobileNav 只有探索/行程/我的；AI 只在选地区阶段出现，地图藏在折叠菜单，更多能力藏在 ACTIVE 分支或旧界面。
5. Qoder 已实现有效会话续期，但关闭标签或完全过期后没有重新认证路径。换个按钮名不能补上身份体系。

## 2. 产品逻辑重构：先有任务，不必先有正式行程

### 独立的两条状态轴

- Agent 任务：ACCEPTED → WORKING → PARTIAL_READY / NEEDS_DECISION → WORKING → COMPLETED；支持 CANCELLED、FAILED_RECOVERABLE、RESUMABLE。
- 旅行方案：PROVISIONAL → REVIEWABLE → SELECTED → ACTIVE → COMPLETED。

AgentRun 的有效性由真实模型请求、工具调用、任务绑定和落库决定，**不能要求先存在 ACTIVE Journey 才允许开始查资料、比较和规划**。正式执行仍遵守现有权限及用户选择，不能把草稿冒充已确认方案。

复用现有 AgentRun/AgentRunStep、JourneyIntent、JourneyMission、PlanVersion、RecoveryEpoch 和工具网关；新增目标任务模式及必要迁移，不复制一套平行数据库。普通 DRAFT 规划不能伪造恢复事件、incident 或别人的成员身份。

### 目标型 Agent 循环

读取目标与偏好 → 识别已知事实及决策关键缺口 → 从当前可用工具中自主选择 → 执行并读真实结果 → 更新地图/草案/待办 → 换策略继续或只问一个必要的人类问题。

这是动态选择，不是固定写死“先 A 再 B 再 C”的工具演出。不规定必须制造修改才能算成功；真正无需改变时可以无动作结束，但要交出用户可用的结果。

一位主 Agent 维持共享旅程与目标；确有独立工作时，再并行派来源研究、路线比较、多人协调子任务。不要先搭十个 Agent 的协调框架再等产品出现。

## 3. 信息缺失时如何继续

| 情况 | Agent 应继续做的事 | 用户看到的结果 |
| --- | --- | --- |
| OSM 没营业时间 | 查官方来源/其他允许的数据源、标记冲突与新鲜度、必要时改选 | 暂定行程与具体待核项，不是全局灰按钮 |
| 价格不明 | 查票务/官网；明确区间和估算依据；可提供免费替代候选 | 已知费用、未计入费用、估算范围分开 |
| 地点服务失败 | 保存已有成果，在任务预算内换查询、类别、范围或已许可服务 | 仍能看地图、编辑日程并得到部分结果 |
| 用户说晚起 | 用自然语言理解并持久化，缺精确时刻则提出可修改假设 | 上午留空或标明假设，不把原文当没看见 |
| 明确不开放/限制进入 | 排除该具体活动，寻找可行替代 | 解释替代与影响，其他日期照常规划 |
| 需要付款或不可逆取消 | 准备方案与账单差异，按授权范围执行或集中请求确认 | 一张明确确认卡，不是连续十个权限弹窗 |

证据按字段保存：已核实、用户陈述、估算、未知、相互冲突；来源、采集时间、适用日期独立。用户认可假设不等于来源事实被验证。

本 PR 的 uncertainty_options.py 只是供目标运行器选策略的纯函数基础，尚未接入实际执行。接入者必须在网关执行前重新验证权限与预算，不能把此函数当权限判定器。

## 4. 操作界面重构

**手机**：地图/行程/AI 助手/探索/我的始终易找。用户不管在哪个状态，都能一句话提要求；结果体现为地图上的真实点、可编辑日程、预算及待确认事项，而不只是聊天文字。

**桌面和平板**：同一数据、同一路由的三栏工作台。左侧旅程与日期，中间地图/日程切换，右侧常驻 AI 与真实工作记录。不是把手机长表格拉高放在大屏中央。小屏用可伸缩底部面板，不占住下一步。

首次操作：输入自然语言目标，补真正必要的信息 → 一次选择本次联网/模型预算及授权范围 → Agent 开始工作并逐步填充地图和草案 → 用户改需求或确认。地图瓦片授权可按当前任务记忆，不每次开图反复询问。

每个用户状态都必须有一个有效主动作。例如“继续完善草案”“让 AI 查这两处”“先看地图”，不是永远灰掉的“生成正式方案”。数据不足也要给可操作产物。

工作记录只展示真实任务、工具名、开始结束/耗时、结果、失败与接下来处理什么；不伪造模型心理独白。暂停、取消、刷新恢复必须在同一任务上生效。

## 5. 把已有功能完整接回来

先运行 tools/reform/inventory_capabilities.py 对 Revolution、V8、archive 三个独立 checkout 扫描，再将当前 authority/mainline、commander 指向的代码和历史独有能力补齐。静态扫描不执行后端、不读取密钥，不把源码存在计成 live 成功。

范围必须包括：旅行目标/偏好；地点探索/地图；来源研究/事实获取/估算；多日草案/正式方案；路线/交通/出发；Guardian/天气与现实变化；重规划/备选方案；多人谈判/分头行动/会合；住宿；订单/支付/承诺；通知/收件箱；身份找回；历史/回收站/导出/复盘。

每个能力登记：源文件与来源 SHA → 真实领域函数/API → 模型 schema → dispatcher → 阶段与权限 → 配置状态 → 用户入口 → 合同测试 → 实际运行证据。状态分 SOURCE_ONLY / ADAPTER_NEEDED / CONFIG_REQUIRED / READY_FOR_REHEARSAL / LIVE_VERIFIED。

**不能一口气把所有 HTTP API 暴露成任意执行器。** 为每个能力建立窄工具，自动注入当前用户/成员/任务，参数由 schema 校验；20 个既有工具先检查是否在 runtime 中实际广告和 dispatch。所有工具的读取、联网、花费、领域变更、可逆性和幂等性都必须说明。元数据不是权限本身。

按来源归并服务实现，不照搬 V8 整个页面；发现历史独有代码必须有迁移去向，未接入不得悄悄省略。看见不可用能力就给可恢复原因，而非假装平台没有这个功能。

## 6. 接口与持久化交付（拟新增合同，当前不是已有服务）

优先约定目标任务 API：POST /journeys/{id}/agent/tasks；GET /journeys/{id}/agent/tasks/{task_id}；GET /journeys/{id}/agent/tasks/{task_id}/events?after={sequence}；POST 同任务的 cancel/resume。按现有路由和权限机制命名适配，禁止前端猜测状态。

任务包含 goal、phase、已确认范围、预算、当前证据与草案版本；工具调用记录 task_id、call_id、sequence、效果、耗时、结果引用和可继续策略。断线从游标续读，重启从落库任务续做；付款、取消、确认计划等写入使用既有幂等与事务边界。

一段来源失败只暂停依赖它的动作。无效授权和到期预算请求一次用户决定；其他无关可完成工作继续，不在前端无限加载。

## 7. 两个开发者现在的职责

### Codex：目标型 Agent + 唯一用户工作台

先集成本 PR 的 AI/地图全局入口，在 390、430、1366 宽上实际运行；把临时只读分类建议替换为目标任务模式。将真实工具结果写入同一工作台，支持边生成边修改、直接查地图、草案与正式方案清楚分层。修用户实际卡点，不再以“又跑通两站 GO”作为主要成果。

### Qoder：全部历史能力的工具接线 + 持久身份

停止文案 pass 与重复量尺。第一棒跑静态清单并直接交三个真实 adapter：来源研究/事实获取、路线与交通、多人协商中的可用切片，合同与实际 dispatcher 一起提交。之后带回住宿、订单/费用、通知、历史功能。并行完成可信重新认证，不能用 traveler_id 换凭据；与 Codex 共用一种身份/成员规则。

Qoder 主要维护领域服务、身份、工具适配与迁移，Codex 维护工作台和目标运行器。共享 models/gateway/contract 改动在同一集成 PR 协调。不把两条旧产品树直接整仓互合；两个队伍不再各画一套首页。

### 集成者：一项变更，一条真人路径

唯一产品验收入口仍是 /revolution。旧入口保留给回归，不要求用户在 V8、Revolution、多个端口之间猜。启动器给实际版本/健康/模型状态并能保留用户原数据。正常授权流程下更新服务，不覆盖共享数据库。

## 8. 交付顺序与验收

第一交付：当前卡住页面可以打开地图和 AI，未知营业不影响看图和提问；附同版本实拍与可开实例。
第二交付：一条真实用户目标触发真实工具研究，自主处理至少一个来源失败或缺项，给出可编辑且有信息量的多时段草案，而不是循环分配地点名。
第三交付：选择确认后进入原正式执行能力；发生一个真实可验证变化时，Agent 提出差异及可用替代，不假造天气或闭馆事件。
同时迁移其余能力；不能以“等全功能恢复”拖住每个可用增量。

六个真人任务：两人两天晚起；缺营业资料仍有建议和地图；来源超时自动换策略；修改偏好保留已有成果；同伴偏好冲突可协商；关闭再开经重新认证恢复旅程与任务。

每次回帖只报用户现在能做什么、代码与部署版本、真实任务结果、剩余一个关键阻塞。测试负责发现错误，不代替成果。功能没接入就是没接入，不把 fixture/配置就绪写成真实 Agent 成功。
