## Two specific audited product defects to prioritize

1. `frontend/src/features/discovery/BootstrapDiscoveryPanel.tsx` initializes `sourceKind="MANUAL_PUBLIC_CENTER"`, `latitude=39.12`, `longitude=117.20` for **every new Journey city**. The inputs are already populated, so clicking provider consent and Search can send a Tianjin-area center for an unrelated city without the traveler ever selecting that center. This contradicts the product promise of an *explicitly user-selected* public center. Controlled tests pass partly because they reuse these values. **P0 product correction:** no implicit coordinates; no search until a valid user-chosen center OR deliberate foreground GPS. Do not silently map a city code to a fabricated centroid. Blank fields must remain blank (do not coerce `Number("")` to zero). Changing source method must not carry the previous GPS accuracy or stale location into a manual-center query.
2. The same component reads `readTravelerBearer()` during render but depends on unrelated React renders for a changed bearer to take effect. `loadShortlist` only guards an `active` boolean, not the bearer at request start or an out-of-order request generation. The `focus/visibilitychange` handler clears pending map consent on bearer mismatch but **does not immediately clear `shortlist`, `resumeIntent`, candidate `result` or in-flight responses**. Old A responses can repopulate private A state after a switch to B in the same tab. P0 **private UI leakage/race**: implement a reactive same-tab bearer-change signal in existing `travelerSession` helpers (or equivalent), scope each async response to its initiating identity/Journey/request generation, synchronously hide and clear A-private state on identity change, cancel pending map tabs/links, and close in-flight navigation after a mismatch. Ensure no old A candidate/shortlist/resume appears for B, even for one paint or while B fetch is slow. Server signed read/write checks remain the final authority.

Prefer reusing an existing map/pin picker or safe paste of an explicit public OpenStreetMap map-pin URL; retain clearly labelled manual WGS84 fields as fallback. Do not add an unconsented geocoding or tile-provider request. A map/tile provider disclosure is separate from the subsequent Overpass search consent. If a picker requires a new unauthorized external API, ship the safe manual/paste entry first; never replace consent with a default coordinate.

Show the selected public center (and its provenance: MANUAL_PUBLIC_CENTER or FOREGROUND_GPS) immediately before external query. Warn rather than assert it lies in the Journey's city unless supported by real city-boundary facts. Never use manual center as observed GPS, group presence, route origin, arrival or protected-commitment buffer. Cancellation and blank/invalid center cause **zero provider calls**. Exact query center is member-private, not part of merged group/Operator/offline payloads. Existing R87 live named-POI discovery, R90 shortlist, R91 navigation and R92 resume should remain usable without a new status framework.
