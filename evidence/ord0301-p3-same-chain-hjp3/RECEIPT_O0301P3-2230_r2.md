| 修正 | 本批怎么做 | 落在哪一格 |
|---|---|---|
| ① 不要求证「同一发」 | 收到，但链路既然在，就仍然逐腿带号，不额外花钱 | K1 |

三句话读法：

1. **判据确实是正文的形状，不是状态码。** 都回答 422：正文是产品自己渲染的 `application/json` envelope（323 B）时，两代都把服务器原话 "Request validation failed" 挂在「服务器给出的原因」下面；正文换成 25 B 的裸文本，状态码一个字没变，部署代就改口成「这台设备自己的读数（服务器没给句子）」，未守卫代更直接掉进「连不上服务端」卡片、技术详情块剩 0 个。500 那一侧（21 B 的产品 500 对 208 B 的代具 envelope）同样只随正文翻。
2. **你那条根因链在两代上表现不同，而且差的那一代不在手机上。** 同一条 21 B / text/plain 的产品 500，未守卫代 `dc964086` 落进 NETWORK 卡片（此时 failureReason 为 null，所以归因标签与技术详情整块都不在：详情块 0 个，且 React 把这个异常吞了，page_errors 0 条），部署代 `7856e03f` 走 HTTP_500 + 设备侧标签「这台设备自己的读数（服务器没给句子）」+ 句子 `agent/commands -> HTTP 500`，详情块 1 个。
3. **「连不上服务端」在部署代仍然有一句是真话。** 我把腿在浏览器里掐死（hop 对该号 0 条记录），屏上印 「连不上服务端」+「no readable answer reached this device (network or origin)」，详情块 1 个 —— 这就是 ORD-0302 ② 落进字节后的样子：它只在**真的没拿到回答**时说没拿到。

## 配对证据长什么样（②的发布级）

产品自己答的腿有 4 条，每条：hop 审计行 1 条、浏览器网络栈 1 条、页面 fetch 1 条、状态码两侧相等 True、正文类两侧相等 True；另外有后端进程自己的 access log 逐条佐证（每臂恰好 1 行点名该腿）。举例：

```
P3-223608  号 hjp3p3-e56f4b07d6694004  服务器侧 500 21 B text/plain  写锁由 hop 持有 rows_touched=2  |  屏侧 status=500 解析=False 卡片=HTTP_500
P3-222513  号 hjp3p3-2f47a57d90ed4499  服务器侧 422 323 B application/json  请求被 hop 加了 1 个键  |  屏侧 status=422 解析=True 卡片=HTTP_422
```

这句的范围要说清：`no_second_probe_of_the_backend` 只约束**被计分的读数**——每一臂的服务器侧那一发都来自这一跳为该请求写的审计行。追那个协议层 400 的时候我确实另外往自己的后端端口直发过 3 个 POST（见下文），它们是诊断、不进任何格子；把它们说成"从没发生过"就是替量具遮丑。
