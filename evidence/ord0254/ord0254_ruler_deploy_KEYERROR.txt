Reading of it:
- Everything up to and including phase 3 (union, gate E pre-switch, backup, switch) ran and printed.
- The crash is inside the ruler, at its own line 654, not in my surface and not in my wrapper: the
  loop at lines 649-653 appends `{"surface","base","got"}` when a base IS configured, while the
  "not configured" branch at 647 appends `{"surface","verdict","base"}`.  Line 654 then reads
  `p["verdict"]` unconditionally.
- Consequence: the F-GREEN path of this shipped object cannot reach the end of main(), so the whole
  A-H receipt (which is written after F) is never produced when the operator does the thing the help
  text asks for - setting CNX_DEPLOY_PROXY_BASE / CNX_DEPLOY_TUNNEL_BASE.  With both unset the run
  completes and F is RED by fail-closed design.
- What that means for the commander's 16/16: unaffected, because the selftest's F arms call
  `repeated_verdict()` directly (lines 333-345) and never go through the aggregation in main().  The
  blind spot is in the deploy path, i.e. exactly the path a换代 uses.
- Family: this is the same shape as A-7's "a gauge that reads one observation cannot see the second
  one" - here an arm whose pass path has never been executed.  Fix suggestion left to the owner: make
  the configured branch store its own top-level verdict (or read `p.get("verdict")`/`p["got"]["verdict"]`
  by branch), and add a selftest arm that drives main()'s F aggregation with a live configured base.
