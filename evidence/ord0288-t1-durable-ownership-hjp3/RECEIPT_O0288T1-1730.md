## 0. 大白话（先把好消息和坏消息说清楚，再说这轮的边界）
**好消息是真的**：同一把键跨两个进程发，库里只留一行；杀掉写它的那个进程、重新起一个，那一行还在、还能被读出来当回执用。**所有权在数据库里，不在进程内存里。**
**坏消息也是真的**：某一发**抢到键却没把答案落下去**（我这轮在私有副本里注入一枚未处理异常造出来），那一行就永远停在 `response_status = None`；此后谁拿这把键再来，都只会拿到同一句 409「agent idempotency record is incomplete」——**调用方分不清“对方还在算”和“对方早死了”，而这把键永久作废。**
**这轮的射程要说白**：本批共 9 发带键请求（1 发 409、8 发 422），`plan_versions` 到收尾仍是 [0, 0, 0, 0, 0, 0] —— 也就是说“耐久”是在一枚**拒绝回执**上量到的，200 带方案的回执重放本批没测（C7 里具名）。
**还有一句不藏**：“同一份答案”我按 JSON 值判（去掉 `error.trace_id`），原始字节**并不相等**（`raw_bytes_equal = False`），因为 `error.details` 重新序列化时键的插入顺序不同（`details_key_insertion_order_differs = True`）。写进件里，免得这句话被读成“逐字节相同”。
